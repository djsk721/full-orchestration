# Background Execution

<!-- feature: background IMPLEMENTED -->

## 개념

기본 포그라운드 작업은 활성 데스크톱 세션에 연결됩니다. Background Execution을 사용하면 UI를 닫아도 같은 사용자 계정의 별도 Supervisor가 실행을 유지합니다. 상태와 체크포인트는 로컬 SQLite에 저장됩니다.

## GUI 사용 방법

1. **모델 및 실행 설정**의 `settings`에 `"background": true`를 저장합니다.
2. **새 작업**의 최상위에 `"background": true`를 넣고 작업을 제출합니다.
3. 대시보드에서 실행 모드와 상태를 확인합니다. 창을 닫았다가 다시 열면 같은 데이터 폴더의 작업, 이력과 이벤트가 표시됩니다.
4. 진행 중인 작업에는 **중지**, 실패한 작업에는 **재시도**를 사용합니다. **Supervisor 종료**는 백그라운드 작업에 영향을 주는 별도 조작입니다.

## 실제 예제

[시작하기](getting-started.md)의 QA 전용 작업을 백그라운드로 제출해 이력 표시를 확인하세요. 대시보드의 실행 모드와 `qa.result`를 확인하고 앱을 다시 열어 같은 작업을 선택합니다. 더 오래 걸리는 읽기 작업이라면 앱을 닫은 뒤에도 Supervisor가 진행합니다.

## 오류 해결

- 포그라운드로 표시되면 레지스트리와 작업 양쪽의 `background` 설정을 확인합니다. 제출된 작업은 당시의 설정 스냅샷을 사용합니다.
- 비정상 종료 후에는 새 Supervisor가 이전 임대 만료를 확인할 때까지 기다립니다. 복구 기록은 `job.recovered`에서 확인하세요. 시작된 외부 쓰기의 결과가 불명확하거나 Attached CLI가 실행 도중 끊겼을 때는 무조건 재호출하지 않습니다.
- UI 알림은 앱이 열려 있을 때의 선택 사항입니다. 실행 이력은 대시보드와 **JSON 보고서 저장**으로 확인합니다.

## 고급 설정

백그라운드에서 Git 파일을 쓰려면 `settings.allow_background_write`를 따로 켜야 합니다. 로그인 시 Supervisor를 시작하려면 Windows 빌드 후 [운영 환경](../admin-guide/operations.md)의 작업 스케줄러 절차를 따르세요. 절전, 로그아웃, 재부팅을 가로지르는 무중단 실행을 전제로 운영하지 마세요.
