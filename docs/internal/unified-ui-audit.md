# Model Orchestration — Unified UI Audit & Legacy Duplication Analysis

## 1. Executive Summary

Before consolidation, the Model Orchestration desktop application (`WorkspaceDesktop`) combined two distinct UI generations inside a single Tk window:

1. **Legacy Desktop Shell (`orchestra/desktop.py`)**: Created via `WorkspaceDesktop.layout()` calling `super().layout()`, constructing `nav_scroll_canvas`, `nav_inner`, `_nav_group_labels`, `NAV_GROUPS` (11 sidebar items), `sidebar_footer`, `header_bar`, `header_new_task`, `header_workers_badge`, `header_notice_badge`, and `host`.
2. **Orca-Inspired Workspace Shell (`orchestra/workspace_shell.py`)**: Overlaid onto the legacy shell via `build_workspace_sidebar()` and `workspace_page()`, adding `workspace_sidebar`, a second toolbar (`workspace_actions` and `workspace_view_actions`), and a second footer (`workspace_status` and `workspace_runtime_status`).

Whenever an operator switched between `"workspace"` and any administrative screen (`jobs`, `agents`, `projects`, `providers`, `ssh`, `hosts`, `mcp`, `history`, `settings`, `submit`, `dag`, `remote_runs`, `registry`), `IntegratedWorkspace.workspace_show(active)` swapped the active sidebar (`nav_scroll_canvas` ↔ `workspace_sidebar`), resized `nav_frame` (`230` ↔ `252`), and packed/unpacked header controls (`header_new_task`, `header_workers_badge`, `header_notice_badge`).

## 2. Exact Duplicated & Conflicting Elements Identified

| Category | Legacy Implementation (`Desktop` / early `WorkspaceDesktop`) | Overlaid Workspace Implementation (`IntegratedWorkspace`) | Consolidation Resolution |
| --- | --- | --- | --- |
| **Application Shell** | `Desktop.layout()` built sidebar + header + `host` frame | `workspace_page()` built a nested toolbar + `workspace_panes` + footer inside `host` | Replaced with one `build_unified_shell()` called once from `WorkspaceDesktop.layout()` |
| **Navigation Sidebar** | `nav_scroll_canvas` + 11 `NAV_GROUPS` rows (`252px`) | `workspace_sidebar` (`workspace_search`, 3 buttons, `workspace_tree`, `230px`) | Consolidated into one `236px` sidebar (`nav_frame`) with search, 5 `NavRow` items (`PRIMARY_NAV`), `workspace_tree`, and 2×2 utility strip |
| **Sidebar Switching** | Shown whenever `view != "workspace"` | Shown only when `view == "workspace"` via `workspace_show()` | Retired dual-sidebar toggling; `workspace_show()` only toggles `sidebar_hidden` |
| **Global Header** | `header_bar` (`sidebar_picker`, `header_env_badge`, badges, `theme_btn`, `header_new_task`) | `workspace_actions` + `workspace_view_actions` inside `workspace_page()` (`새 작업`, `터미널 ▾`, `workspace_model_picker`, `보기 ▾`, `집중`) | Merged into one full-width `48px` `header_bar` with one project picker, one `새 작업` button, terminal/model controls, status badges, view menu, focus toggle, and theme toggle |
| **Status Bar** | `sidebar_footer` + `self.status` | `workspace_status` + `workspace_runtime_status` at bottom of `workspace_page()` | Unified into one full-width `status_bar` at window row 2 (`workspace_status`, `workspace_runtime_status`, `header_workers_badge`) |
| **Theme Default & Refresh** | `"dark"` default; multiple raw `tk.Label`/`tk.Frame` widgets in `Card`s did not recolor on theme toggle | Dark terminal canvas + mixed light/dark card inner frames | Minimal `"light"` Orca default (`#ffffff` canvas, `#f6f7f9` sidebar, `#fafafa` header) + `retheme_widget_tree()` and `track_themed()` across all screens |
| **Font Resolution** | Tuple `("TkDefaultFont", 10)` risk when fallback returned named font ID instead of family name | Same `resolve_fonts()` | Platform-aware scalable candidates (`Segoe UI`/`Malgun Gothic` on Windows; `Noto Sans CJK KR`/`NanumBarunGothic`/`DejaVu Sans` on Linux) with X11 `gothic` fallback and actual-family resolution |
| **Settings & Admin Access** | Separate global nav groups (`EXECUTION`, `INTEGRATIONS`, `SYSTEM`) | Command palette and hidden routes | Accessible via unified `settings` hub (`SettingsSection`), 2×2 sidebar utility strip, and `Ctrl+K` palette, all opening inside `workspace_book` tabs |
